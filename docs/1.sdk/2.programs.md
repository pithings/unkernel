# Run Programs

> Run guest programs on pipes or on their own pty.

## `exec()`

```js
const { stdout, exitCode } = await vm.exec("uname", ["-a"]);
const { stdout: sum } = await vm.exec("sha256sum", [], { input: "hello" });
```

`exec()` runs a program on pipes and resolves with `{ stdout, stderr, exitCode, signal }`, also for a non-zero exit. Pass `encoding: "buffer"` for bytes, and `cwd` or `env` as you would to `child_process`.

On the distro images programs run as the user `user` (uid 1000, in `/home/user`), who has `sudo` without a password. Pass `user: "root"` (or another name or uid) to run as someone else. The base shell is root's.

## `spawn()` on a pty

```js
const sh = await vm.spawn(); // a login shell on its own pty
sh.output.pipeTo(new WritableStream({ write: (b) => process.stdout.write(b) }));
await sh.write("cat /etc/alpine-release; exit\n");
console.log(await sh.ended); // { type: "exit", code: 0 }
```

`spawn(file, args, { cols, rows })` runs a program on a pty, in the zigpty / node-pty shape, with `resize()`, `kill(signal)` and `close()` (a hangup). Run as many as you like.

::warning
Keep reading `output`: the guest program waits while nobody does.
::

## `spawn()` on pipes

```js
const gz = await vm.spawn("gzip", ["-c"], { pty: false });
gz.stderr.cancel(); // read both outputs, or cancel one
const zipped = new Response(gz.stdout).bytes();
await new Response("hello\n").body.pipeTo(gz.stdin); // then EOF
console.log((await zipped).length);
```

With `pty: false` the program gets pipes: `stdin`, `stdout` and `stderr` web streams, byte for byte.

## Read and write guest files

```js
import { readGuestFile, writeGuestFile } from "unkernel";

await writeGuestFile(vm, "/home/user/data.bin", new Uint8Array([0, 1, 2, 255]));
const bytes = await readGuestFile(vm, "/home/user/data.bin");
```

`readGuestFile(vm, path, opts?)` and `writeGuestFile(vm, path, bytes, opts?)` transfer a single regular file as a buffered `Uint8Array` at a guest-absolute path. Both accept `user` (defaulting to the guest's default user) and `signal` (`PtyError` `ABORTED`), and `readGuestFile()` accepts `maxBuffer` (default 64 MiB).

When a persistent data disk is attached, write to merged guest paths such as `/home/user/...` for the live overlay. Direct writes under `/data` require a directory writable by the selected user (on the distro images `/data` is owned by `root` with mode `0755`, while the default user is `user`, uid 1000) or `user: "root"`.

`writeGuestFile()` requires an existing parent directory and rejects destinations that are symlinks or non-regular files. It verifies the bytes written to a temporary file before atomically replacing the destination with a new private file owned by the selected user. Aborting asks the guest to remove the temporary file. If the guest stops responding, the temporary file may remain. A rename that completes during cancellation takes effect. Call `vm.sync()` or power off cleanly for disk durability.

Both helpers buffer the whole file in memory. For large or streamed transfers, use `vm.spawn(..., { pty: false })` on pipes directly.
